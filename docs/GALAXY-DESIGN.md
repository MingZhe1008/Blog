# 星图航行：前台视觉改版设计

## 1. 目标

将博客从“暖色终端”改造成可探索的个人知识星系。首页承担导航与发现功能：读者像查看星图一样浏览文章，但文章标题、摘要与入口仍保持清楚易读。文章详情页减少装饰，只保留低亮度星尘与轨道刻度，避免影响长文阅读。

成功标准：首屏一眼可识别为个人星系；文章入口像星系节点；导航由太阳、月亮、星星等天体构成；手机端仍可顺畅浏览；开启“减少动态效果”后不出现持续运动。

## 2. 方案比较

### A. 静谧天文台

- 深蓝夜空、黄铜刻度、月相导航，文章维持规整列表。
- 优点：阅读稳定、性能最好。
- 缺点：子节点不像真正的星系，可记忆点较弱。

### B. 星图航行（推荐）

- 首页为二维星图；文章节点沿不规则轨道分布，每个节点都有独立星云色和行星环。
- 优点：最贴合“子节点是星系图标”，互动与内容结构能自然结合。
- 缺点：需要细致处理响应式布局与动效降级。

### C. 深空舷窗

- 使用 Canvas/WebGL 构建可拖动、缩放的三维星场。
- 优点：沉浸感最强。
- 缺点：实现与维护成本高，影响首屏性能、SEO 和无障碍体验。

## 3. 推荐视觉系统

采用“星图航行”。主背景为墨蓝黑 `#050711`，由两层 CSS 星点、一层缓慢漂移的星云和低透明噪点构成。主强调色为月光银 `#F4E9C9`，辅色为电光青 `#77E8D6`、日冕橙 `#FFB45B` 与星云紫 `#A78BFA`。不使用常见的整屏紫色渐变。

标题继续使用有文学气质的衬线字体，界面小字使用窄体无衬线/等宽字体，形成“天文图册”感。装饰线统一为轨道弧线与星图刻度，卡片不使用普通圆角矩形。

## 4. 首页结构

顶部导航是一条轻薄的“天体轨道”：太阳代表首页，星簇代表文章，月亮承担明暗模式；语言切换表现为小型坐标标记。当前页面对应的天体会出现光晕与轨道标记。

Hero 左侧展示名字、简介和“进入星图”入口；右侧是一颗缓慢自转的个人主星，周围有三条轨道与小型卫星。下方文章区使用不对称星图布局：每篇文章是一个可点击的星系节点，图标由核心、旋臂、轨道和卫星组成；标题、日期、标签沿节点旁的引导线排布。节点悬停时旋臂轻微加速、摘要浮现，点击仍进入标准文章详情页。

无文章时显示一颗低亮度“尚未点亮”的恒星，并保留前往文章页的入口。

## 5. 其他页面与组件

- 文章列表：使用星图目录，筛选标签作为“星域坐标”，列表项使用更紧凑的行星节点。
- 文章详情：保持单栏阅读；页头变为观测记录，目录为右侧星座连线，正文背景仅保留静态星尘。
- 导航页/关于页：以星星、月亮、彗星组成入口，不依赖 emoji，全部用 CSS/SVG 绘制。
- 管理后台：保持现有实用布局，只同步颜色变量，不引入星流动画。

## 6. 动效与可访问性

背景星流只使用 `transform` 与 `opacity`，避免持续触发布局；节点仅在可交互状态下增强光晕。移动端减少星点数量并将星图重排为纵向航线。所有天体图标都保留可读文字标签、键盘焦点状态和足够对比度。

当系统启用 `prefers-reduced-motion: reduce` 时，停止星流、旋转与漂移，只保留静态层次。主题切换时同时改变星空密度与光度，而不是简单反转颜色。

## 7. 实现边界

首轮只改公共前台外观与首页核心交互，不改变数据库、文章 CRUD、路由和 i18n 数据流。视觉元素优先使用 CSS 与内联 SVG，避免引入 WebGL 和大图片依赖。完成后以 TypeScript、生产构建与桌面/移动端视觉检查作为验收。
